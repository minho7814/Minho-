# Minho 문자 정렬 알고리즘

﻿이건 제가 러시아어를 키보드로 치는데 자판 배열을 몰라서 한번씩 다 검사하다가
 
“어떻게 해야 안 외우면서도 손가락을 덜 쓸까?”

라는 아이디어에서 출발했습니다.


처음에 n길이의 순열(실제 상황에선 문자열)이 1글자씩 들어오는데,
12345처럼 원래 수열이 아닌 21354처럼 섞인 수열이 들어오는데
(원래 문자열이 뭔지 안다)
이것을 처음의 정렬된 상태로 만들어야 합니다.

# 명령어
(비용 0) `in x` : 현재 커서 위치에 들어온 문자(x라고 명시)를 삽입.

(비용 1) `ptr--` : 커서 위치를 한칸 왼쪽으로. (12|3 -> 1|23)

(비용 1) `ptr++` : 커서 위치를 한칸 오른쪽으로. (12|3 -> 123|)

(비용 1) `push`: 현재 입력된 문자를 임시 배열의 뒤에 추가.

(비용 1) `pop`: 현재 임시 배열의 맨 앞에 있는 문자를 꺼내 현재 커서 위치에 삽입.


여기서 임시 배열은 FIFO 큐를 의미합니다.

# 예시
14235이라는 수열이 순서대로 들어올때 

이걸 원래 형태인 12345로 바꾸는 방법:

`[현재 수열] 명령` 형식. (커서는 |)

`[1|] in 1`

`[14|] in 4`

`[12|4] ptr--` in 2 (14| -> 1|4 -> 12|4)

`[123|4] in 3`

`[12345|] ptr++ in 5` (123|4 -> 1234| -> 12345|)

총 비용 2.

54321의 경우:

`[5|] in 5`

`[4|5] ptr-- in 4` (5| -> |5 -> 4|5)

`[3|45] ptr-- in 3` (4|5 -> |45 -> 3|45)

`[2|345] ptr-- in 2` (3|45 -> |345 -> 2|345)

`[1|2345] ptr-- in 1` (2|345 -> |2345 -> 1|2345)

총 비용 4.

# 구현 - 강한 전수조사
이것은 비트마스킹을 이용한 최적화와 전처리로 vector 복사 비용을 없애고
삽입 비용을 없애서 $O(2^N N^2)$까지 최적화를 시켰습니다.
사용된 기법:
-> 현재 수열, 큐에 사용된 집합은 arr의 부분 집합이므로 비트마스킹으로 표현하여 복사 비용을 없앤다.
-> 현재 수열에서 K번째 원소는 집합만으로 알 수 없으므로 모든 부분집합을 정렬했을때 K번째 원소를 미리 전처리하여 구해 놓는다. (main2.cpp에서 kth)
-> 현재 수열, 현재까지 처리한 원소 갯수만 알아도 큐의 원소와 순서를 유일하게 복원할 수 있으므로 큐를 상태에서 제거한다.
전체 코드는 main2.cpp 파일에서 확인하실수 있습니다.
